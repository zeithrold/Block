# 本轮交付：ActionMenuList 与首次设置 GameChoice

两个 HTML 原型已认可。本文定义原生交付范围与门槛；原型通过不等于原生验收通过。

- [操作行图标原型](../action-list-card-preview.html)：以 Microsoft 浏览器等待页说明操作图标与去向标记的分工。
- [GameChoice 原型](../game-choice-loading-preview.html)：在预览器切换加载中、成功、失败，比较同一推荐行。预览器的状态选择器不进入产品。

## 共享组件与迁移边界

仅迁移 Button 类型的整卡操作或导航入口，相关操作放在同一 `ActionMenuList`。按实际行为而不是外观或函数名盘点。单选、多选 Card 本轮不迁移；只读信息卡，以及仅有内部按钮能点、容器本身不能点的卡片也不迁移。

行左侧图标说明操作对象，标题与说明左对齐。右侧表达实际行为：站内前进、外链或加载状态。保留已有状态徽章、禁用原因、键盘和无障碍语义。调用方迁完后退役对应的 Button Card 实现，保留选择控件和基础只读 `card()`。

| 核对面 | 交付点 |
|---|---|
| 首次设置总览、添加账号 | Account / Game、Microsoft / Authlib / Offline 改为操作行；保留配置状态、导入数量、可用性及其他登录方式的展开行为。 |
| Microsoft 浏览器授权等待页 | 将现有 `ActionListCard` 操作纳入同一组件：重新打开登录页是外链，改用设备代码是站内前进。 |
| GameChoice、游戏设置与详情 | GameChoice 按下节交付。版本、Loader、配置、OptiFine 等整卡入口保留摘要和去向；详情页只迁可交互项。 |
| 排除：语言、导入与配置选择 | 语言、导入来源与候选游戏、共享／隔离策略、具体版本与 Loader 的单选或多选卡全部保持原样；打开选择页面的整卡按钮可以迁移。 |

普通 Wizard 第一步的普通按钮不因外观有边框就纳入；只读登录进度、HTTP 警告、结果说明也不改成菜单。

实现盘点时另作区分：添加账号的 Microsoft 行启动授权，Authlib / Offline 行打开表单，属于操作而非单选；语言、导入来源和候选项分别保留原有 Radio / Checkbox，行内的查看与策略按钮仍独立。Home 的启动／切换按钮是分段主操作，不是菜单卡；下载进度与 Toast 也不在本次迁移内。

## GameChoice：四行与三种状态

顺序为 **推荐配置、自定义配置、导入整合包、导入已有游戏**。删除单独的 `Import existing games` 按钮，不删除导入能力；列表里的同名行打开原来的扫描 Drawer，不新增目录选择器。从总览点 Game 时，已经发现安装就直接打开 Drawer 的分流不变。

删除此页常驻的 `Reload versions`；不影响版本选择页自己的刷新入口。版本列表仍自动加载，状态只占推荐行：

| 状态 | 推荐行 | 点击结果 |
|---|---|---|
| 加载中 | 文案“正在加载 Minecraft 版本列表…”；右侧等待环替代箭头 | 暂不可点，其余三行仍可用。减少动态效果时保留文字。 |
| 成功，有可用正式版 | 显示推荐版本与原版摘要，恢复前进箭头 | 以显示的版本预填配置页。 |
| 失败，无可用版本 | 明示列表不可用，以及将使用的内置固定版本，恢复前进箭头 | 以显示的内置版本继续，不强制重试。 |

固定回退版本为 `1.21.1`，只用来预填推荐配置，不伪造在线列表或承诺离线安装。首次设置仍只保存，不因选择推荐或回退版本触发安装。

## 原生验收条件

- 按 Button Card 的实际调用方逐项记录迁移或排除理由；核对选择卡、只读卡及普通控件不受影响。
- 在 Linux ARM64 的 360×720 内容区核对浅／深色、中文换行、尾部标记、键盘焦点、选中与禁用态；交互验证用真实入口，不以 HTML 预览代替。
- 让版本请求分别保持加载、成功及失败；检查等待环与箭头互斥，其他入口可操作，成功和回退时显示版本与实际预填版本一致。
- 从总览和 GameChoice 分别进入导入 Drawer，验证返回路径、选择与次要操作；验证外链与站内导航未混淆。

## 推送与完成条件

1. 推送前，Linux ARM64、Linux AMD64、Windows AMD64 三台测试平台验证与本机完整 `just check` 必须都通过；上述 Linux ARM64 原生验收不能用 HTML 原型替代。
2. 两项均通过后才推送。跟踪所推提交的 CI；排队、运行中或失败都不算完成。
3. 如有失败，修复并复验后再推送。只有最终提交对应的 CI 全绿，才结束交付。
