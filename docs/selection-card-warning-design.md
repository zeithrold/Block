# 选择卡片与导入警告设计

日期：2026-11-10。状态：产品实现、自动化回归与 Linux ARM64 原生验收已完成。

本轮需求：统一所有选择卡片 Indicator 的居中方式；把导入实例选择器中的隔离风险提示缩小并放入卡片；通过非线性、小幅、可打断的扩张表现提示出现；其余警告遵循“只提示当前待处理风险”的规则。

## 调查结论

这里的导入实例选择器指 ImportGames 的实例列表。主页已有实例/账户选择器也纳入 Indicator 排查，但没有导入隔离风险，不新增此类警告。

| 表面 | 源码与当前机制 | 结论 |
| --- | --- | --- |
| 导入来源卡片 | `import_games.rs:1125` 附近使用 `radio_row`；内部文字列 `items_start` | 外层继承共享居中；文字列的左对齐不等于 Indicator 顶对齐 |
| 导入实例卡片 | `import_games.rs:1269` 附近使用 `checkbox_row` | 继承共享居中；风险提示目前是卡片外的独立 Alert |
| 共享/隔离选项卡 | `import_games.rs:929` 附近使用 `radio_row`，随后 `items_start`（约 949 行） | 明确覆盖了外层垂直居中，导致长卡片的 Radio 靠上 |
| 语言选择卡片 | `navigation/shell.rs:1369` | 外层共享居中；内部语言名称与译名自行布局，无明确顶对齐缺陷 |
| 主页实例选择器 | `controls/search_selector.rs:396` | 自定义按钮、36px Avatar、文字列和尾部 Radio；依赖按钮默认对齐，没有共享卡片的显式约束 |
| 主页账户选择器 | 同一 `selector_row` | 同上；键盘活动项与实际当前项是两个状态，不能混为选中 |

源码位置随后续编辑可能移动，函数名为定位依据。

`controls/components.rs::choice` 在外层设置 `items_center`；行式选择追加反向排列和 15px 内衬。边框占用布局后，现有选择器测试观察到的右侧净距离是 16px。`selection_motion.rs::indicator` 已经使用固定 16×16 盒子，Radio 围绕 `bounds.center()` 绘制，Checkbox 路径也相对盒子中心。问题应在布局所有者修复，不能靠移动圆点或对勾补偿。

现有 `search_selector.rs` 的原生控件测试检查了 16×16 和右侧 16px，但没有检查 `indicator.center.y == card.center.y`。这使顶对齐覆盖不容易被回归检测到。

相邻但不同的控件：

- 游戏管理列表的 `ListBoxOption` 表示“正在查看”的记录，尾部当前项标记另有意义；不改成 Radio 卡片。
- Select 菜单项、表单内的小 Radio/Checkbox 继续作为紧凑控件。
- 新建游戏、导入整合包等入口是操作按钮，不增加选择 Indicator。

### 警告为何显得到处都是

1. `import_data_status` 把“当前选择共享”直接当成持续警告，没有区分默认采用与用户已确认。
2. `render_list` 只排除了不可导入和已导入项，未勾选项也会生成独立风险 Alert。
3. 模式未知的候选项默认隔离；列表默认勾选多个候选，因此多个大 Alert 同时出现。
4. `SelectDataPolicy` 当前会记录确认，但 `import-policy-done` 只执行 Back。保留默认选项后直接点“应用”，不等于代码中的确认。
5. 重新扫描按候选 ID 保留 `acknowledged`，没有把确认绑定到真正的数据位置判断依据。

## 统一几何

唯一标准是**整张可见选择卡片的几何中心**，包括卡片内展开的风险文字；不是标题中心、第一行基线或文字列中心。

- Indicator：16×16，不伸缩；单选 Radio，多选 Checkbox。
- 水平位置：卡片可见右边界到 Indicator 可见右边界净距 16px。
- 垂直位置：`indicator.center.y = card.top + card.height / 2`。
- 允许物理像素栅格造成最多 0.5 个物理像素的误差；不能把 0.5 逻辑像素当成所有 DPR 的容差。
- 文字左对齐，标题 14px/20px、加粗；辅助文字 12px/18px。
- 内容左右净内衬 16px，文字与 Indicator 间距 12px，兄弟卡片间距 8px。
- 共享的选择卡片布局所有者负责外层交叉轴居中；调用方只负责文字列布局，禁止再覆盖为外层 `items_start`。
- 动画期间也按当前可见高度计算中心。禁止给 Indicator 单独加 `mt`、`top` 修补或独立滞后的位移动画。
- 选中状态使用原有背景与 Indicator；键盘焦点保留独立 focus ring，不能把焦点轮廓当成选中边框。
- 不改变页框、Drawer 标题、返回按钮、固定操作区和滚动条外侧留白。

## 导入实例卡片

Layout: 导入选择列表 — 保持单列和局部展开 -> scroll-body-shell（https://github.com/changeroa/StyleGallery/blob/main/patterns/viewport-shell/scroll-body-shell.md）；scroll owner: 现有 `import.list`；固定标题与操作区；禁止另造嵌套竖向滚动、卡片宽度缩放和卡片外逐项 Alert。

主操作：添加所选实例。阅读优先级：实例名称/版本 → 当前数据模式 → 需要处理的风险。

```text
┌──────────────────────────────────┐
│ Creative                         │
│ 1.21.1 · Vanilla · 隔离   调整    │   [Checkbox 在整卡高度中心]
│ 暂用隔离，原有数据可能不可见。    │
└──────────────────────────────────┘
```

警告是卡片内文字，不是另一张小卡片：

- 12px/18px，正常字重，使用 `warning` 语义色；不加独立黄色背景、边框、粗体标题或大 Warning 图标。
- 和元数据间距 8px；正常中文一行时增高约 26px。英文、日文和窄宽度可自然两行，增高约 44px，不截断风险含义。
- 原有卡片选中背景维持不变；警告与勾选状态分别表达，不能用黄色整卡表示选中。
- “调整”是独立的可聚焦操作，目标至少 24×24px。它打开同一 Drawer 内的数据位置页，不切换实例勾选状态。
- 选择动作与“调整”在语义树中是兄弟控件，不把一个按钮嵌进 Radio/Checkbox 控件里。外观仍只有一张卡片。
- 详情路径仅保留在来源卡片和共享/隔离选项卡内，实例风险文字不恢复路径。
- 选项卡展示实际绑定的游戏目录，包括已检测到的外置隔离目录。原型中的 `versions/...` 是示例路径，不是重算现有目录的产品规则。

拟定简短文案：

| 状态 | 卡片内文字 |
| --- | --- |
| 未知、尚未确认 | 暂用隔离，原有数据可能不可见。 |
| 默认共享、尚未确认 | 共享数据可能影响其他版本的维护。 |
| 明确隔离 | 元数据中的“隔离”，不出现风险段落 |
| 已确认共享/隔离 | 元数据中显示当前模式，不再出现风险段落 |
| 未勾选 | 保留模式和“调整”入口，收起风险段落 |

这里的“隔离风险”覆盖未知位置时暂用隔离，以及已检测共享、将草稿改为隔离但尚未应用的情形；不能给明确检测为隔离的实例制造此提示。

## 各页出现规则

| 场景 | 设计规则 |
| --- | --- |
| 来源页，一个有效候选 | 只对所选来源中的待确认风险提供一处入口；风险附着在该来源卡片内 |
| 来源页，多个候选 | 来源卡片只显示待确认数量和进入实例列表的入口，不展开逐实例解释 |
| 实例列表 | 每个勾选且未确认的风险用所属卡片内短文字表达；在已有“已选数量 / 全选”行中显示“2 项待确认”，不另占一行或使用黄色汇总卡片；无待办时只隐藏该短文字，不改变行高 |
| 数据位置页 | 两张 Radio 选项卡解释 Shared/Isolated 与实际路径，不再叠一张警告 |
| 不可导入、已导入 | 没有模式警告；保留不可导入原因或已导入状态 |
| 进度与结果 | 没有模式警告；执行失败仍在对应实例结果卡片内展示 |
| 主页实例/账户选择器、语言页 | 只有选择状态，不引入导入数据风险 |

页头汇总只负责待办数量；卡片文字解释不同风险。单个待办可以直接进入它的模式页；多个待办的汇总入口定位首个待确认项并聚焦其“调整”，不自动替用户修改模式。

## 确认与返回

以数据位置页的“应用到草稿”为确认边界：

1. 点选 Shared/Isolated 更新当前草稿并预览选中状态，暂不确认。
2. 点“应用”确认当前有效选择，即使用户没有重新点击已选中的默认项，也必须确认。
3. 返回保留草稿选择和原行焦点。只浏览后返回，不把风险当成已处理。
4. 取消勾选收起风险，但不删除已有确认；重新勾选恢复当前有效确认。
5. 确认属于本次导入 UI 会话。切换来源、返回、同证据重新扫描不清空。
6. 确认与候选的数据依据绑定：检测模式、资源根、实际游戏目录和所选模式。相关值改变后才重新提示；不因无关扫描时间、主题或语言变化清空。
7. 导入仍遵守现有有效性规则，风险提示不新增强制逐项确认的阻断。

## 卡片的非线性小扩张

扩张表达“这个被选择的实例还有一条需要看的风险”，只增加内容所需高度；不做整卡放大，不缩放文字，不改变宽度和邻居间距。

| 通道 | 设计值/行为 |
| --- | --- |
| 警告区域高度 | 测量当前语言与可用宽度下的自然高度；0 ↔ 文本高度 + 8px |
| 高度响应 | 采用过阻尼或临界阻尼的小弹性响应；一行提示约 300ms 进入视觉静止（距终点小于半个物理像素），不做可见反弹；长文按同一响应自然收敛 |
| 初始 Web 原型参数 | 质量 1、刚度 520、阻尼 46，作为手感候选，不宣称等于 GPUI 的内部参数 |
| 内容进入 | 随可见高度淡入，最多 2px 的向下到位；文字始终保持实际字号 |
| Indicator | 保留现有 160ms 勾选绘制/Radio 状态变化；几何中心随卡片当前高度同步 |
| 相邻卡片 | 随同一高度样本自然下移/上移，不另排一个等待队列 |
| 打断与反向 | 从当前高度与速度转向新目标；快速勾选/取消不跳端点、不锁输入 |
| 初次打开列表 | 已存在的选中状态直接以最终几何出现，不逐张播放入场扩张 |
| 减弱动态效果 | 高度、Indicator、滚动和命中区域立即进入最终状态，不保留隐藏警告的焦点或透明可点击控件 |
| 语言/宽度变化 | 重测实际文本高度；不使用固定 `max-height` 裁剪文字 |
| 滚动锚点 | 保持当前操作卡片顶部位置；只在焦点控件将被固定操作区遮挡时最小滚动，不整页跳顶 |

实现继续由卡片组件持有局部运动状态，Drawer 保留自己的尺寸与页面转场所有权。现有 `drawer.rs::DrawerFrame::sample` 已使用 `spring` 和约 260ms 的本地高度过渡，可复用已有运动设施；不引入新动画库。具体 GPUI 参数通过组件测试和原生采样确定。

原型首轮捕获发现：若数量汇总独占一行并随 0→1 出现，卡片会先整体跳动约 30px，再开始小扩张。因此汇总已合并进现有计数行；这条稳定行高约束必须保留。

参考了 beui 的 Bouncy Accordion：测量内容、共享布局响应、区分展开与收起、支持 reduced motion；其演示使用更明显的 bounce，本设计不照搬。原始代码：https://beui.dev/r/bouncy-accordion/raw

单选组的键盘与语义约束参考 WAI-ARIA Radio Group Pattern；卡片布局统一不改变单选互斥、方向键切换和焦点入口：https://www.w3.org/WAI/ARIA/apg/patterns/radio/

## 实施与原生验收

`components::selection_card` 让原生选择控件覆盖整卡，正文和“调整”作为兄弟内容组合；Indicator 由完整卡片的布局居中。`controls/selection_reveal.rs` 直接测量原生文字、驱动像素高度 Spring，并处理首帧、反向、重新挂载和减弱动态效果。`import_games::State` 将风险、草稿、确认和有效提交分开，重新扫描也重新验证实际目录。

格式检查、UI 包所有目标及特性的严格 Clippy、627 项单元测试和 3 项集成测试通过。新增的真实标题命中断言另行通过定向测试及最终静态检查；重新扫描的目录回归保留了修复前失败、修复后通过的证据。未运行整个工作区的 `just check`，未把 UI 验证扩展为游戏启动或账户认证验收。

推送前另行导出本轮暂存代码，排除既有字体、悬停等未提交改动，独立通过格式检查、严格 Clippy、622 项单元测试和 3 项集成测试。前述 627 项是完整工作区的验证记录；独立提交的检查日志位于同一证据目录中的 `push-index-*.log`。

Linux ARM64 原生检查覆盖六类卡片、浅深主题、中英日文、360 与 432 内容宽度，以及 DPR 1/2。DPR 2 的 8 幅画面中，10 个完整卡片的 Indicator 均为 16×16 逻辑像素、右侧净距 32 个物理像素，中心误差最大 0.5 个物理像素。普通应用流程的原生录制证实快速反向的中间状态；减弱动态效果的轨迹只含最终状态。

DPR 2 使用任务专用的 1600×1700 嵌套 X11 显示，未更改共享桌面分辨率。原始截图、视频、几何数据、完整命令、测试宿主差异和清理收据见 `target/selection-card-implementation-20261110/README.md`。此记录不代表其他操作系统或 CPU 架构已验收。
